# AI 对话简化信息

## 问题

桌宠聊天 UI 目前展示完整的 AI 工作过程（推理 thinking、工具调用 tool/mcp/skill、路径引用 path、状态信息 status 等），信息过载以及过多的边框层级破坏角色扮演沉浸感。需要默认隐藏这些技术细节，只保留关键信息。

## 设计方案

### 1. ChainOfThought 聚合模型

**数据来源**：在渲染层做聚合，不修改 `ChatRuntime` 和 `parts[]` 数据模型。

**聚合规则**：一个 assistant 消息的 parts 按顺序扫描，将连续的非 text part 聚合为一个 `ChainOfThought`：

```
parts: [tool_A, thinking_1, tool_A, tool_B, text_1, tool_A, thinking_2, text_2]

→ 渲染为：
  ChainOfThought_1: [tool_A, thinking_1, tool_A, tool_B]
  text_1
  ChainOfThought_2: [tool_A, thinking_2]
  text_2
```

**分组逻辑**：
- `text` part 作为分隔符，不归入任何 group，独立渲染为"总结文本"
- 连续的 `thinking` / `tool` / `mcp` / `skill` / `status` / `path` parts 聚合为一个 ChainOfThought
- `question` part 独立处理（转移到输入框区域，见第 3 点）

**ChainOfThought 内的 TimelineItem**：
- 同 kind 的连续 parts 合并为一个 item（如连续 3 个 `tool` kind 但 title 不同则为 3 个 item）
- 同 kind + 同 title 的连续 parts 合并为一个 item（如 Bash 被调用 3 次 → 1 个 item，内部展示 3 次详情）
- `thinking` 每次独立为一个 item（思考内容不同，不合并）

**聚合是纯渲染层函数**，输入 `ChatMessagePart[]`，输出 `ChainOfThought[]`，不涉及状态修改。

### 2. 路径点击行为

路径 part（`kind === 'path'`）点击后调用 Tauri 命令：
- **文件路径**：用系统默认编辑器打开文件（需新增 Tauri command `open_file_with_default_app`，Rust 侧用 `open::that(path)` 实现）
- **目录路径**：复用已有 `open_workspace_in_file_manager`

路径由 Node runner 传入，已经是绝对路径（由 Rust 侧 `std::fs::canonicalize` 保证），前端无需额外解析。

### 3. 问答/权限转移到输入框区域

**方案：替换输入框，回答完成后恢复。支持多问题排队。**

正常状态：
```
┌─────────────────────────────────┐
│  输入消息...           [发送]    │
└─────────────────────────────────┘
```

有 pending question 时，输入框被替换为问答区域：
```
┌─────────────────────────────────┐
│  1/3  工具请求权限：读取文件     │
│  ○ 允许  ○ 拒绝                 │
│  [自定义回答...]        [提交]   │
│                        [跳过]   │
│              2/3 ··· 3/3        │
└─────────────────────────────────┘
```

**规则**：
- 存在 pending question（`status === 'pending'`）时，输入框整体替换为问答 UI
- 支持多个 pending question 排队，显示"当前第 N/M 个"，回答完当前自动切到下一个
- 全部回答完毕后自动恢复为正常输入框
- 权限类（`permission`）：显示选项按钮（允许/拒绝）+ 可选自定义文本
- 问答类（`ask-user-question`）：显示选项按钮 + 自定义文本输入
- 支持跳过当前问题（标记为 skipped，切到下一个）

**已回答/已跳过的 question parts**：仍在消息区域以折叠态显示回答摘要（复用 `ToolQuestionAnswerSummary`），方便回溯。

### 4. 总结文本

总结文本 = AI 在工具调用之间自然输出的 `text` part。**不需要前端额外生成或提取**。

当前 `appendPart()` 已经将同 kind 的 text delta 合并为连续文本。渲染时，text part 直接用 `<MessageResponse>` 渲染为 Markdown，这就是"总结文本"。

如果 AI 没有在工具调用之间输出 text（直接连续调用工具），则该 ChainOfThought 后没有总结文本，这是正常情况。

### 5. 历史会话兼容

**渲染层同时兼容新旧格式，无需数据迁移。**

- 历史 localStorage 中的 `StoredConversation.parts[]` 格式不变
- 聚合函数是纯渲染层逻辑，对任何 parts 数组都能正确工作
- 旧会话的 `question` parts（已 answered）仍然渲染在消息区域的折叠态
- 新会话的 pending question 替换输入框显示
- 判断依据：`questionData.status === 'pending'` → 替换输入框，否则 → 消息区域折叠态

### 6. 折叠策略

**不做持久化，默认全部折叠。**

- **ChainOfThought**：初次生成对话时自动展开，后续查看历史时折叠
- **TimelineItem（内部各条目）**：始终默认折叠，用户可手动展开查看详情
- 判断"初次生成"：assistant 消息处于 pending 状态（`runtime.pending === true`）时该消息的 ChainOfThought 展开，done 后下次打开折叠

## UI 结构

```
ChainOfThought （ChainOfThought 组件，标题显示shimmer闪烁的"思考中"，思考完成后显示“已思考”）
  ├─ TimelineItem: 思考    ← 折叠，聚合同名工具
  ├─ TimelineItem: Bash <执行描述>    ← 折叠，聚合同名工具，展开后显示工具的输入和输出内容
  ├─ TimelineItem: Read <文件路径>    ← 折叠，路径可点击打开
  ├─ TimelineItem: Skill <技能名>    ← 折叠
  ├─ TimelineItem: 思考    ← 折叠，聚合同名工具
  ├─ TimelineItem: Bash <执行描述>    ← 折叠，聚合同名工具
  ├─ TimelineItem: Read <文件路径>    ← 折叠，路径可点击打开
  ├─ TimelineItem: Skill <技能名>    ← 折叠
  ...
总结文本
```
