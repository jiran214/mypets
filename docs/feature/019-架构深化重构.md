# 019-架构深化重构

基于架构审查报告，按 #1 → #5 → #2 → #4 → #3 顺序完成 5 项重构。所有改动均为纯重构，无功能变更。TypeScript 和 Rust 均编译通过。

---

## #1 Provider Runner 代码重复

**问题**：三个 provider runner（`run-claude.mjs`、`run-pi.mjs`、`run-codex.mjs`）各自维护相同的工具函数。Pi/Codex 的 `execText` 引用了未导入的 `execFileSync`，导致 `wherePaths` 静默失败。

**改动**：

- 新建 `src-node/runner-utils.mjs`，导出：
  - `existingFile(path)` — existsSync 版文件存在检查
  - `execText(command, args)` — execFileSync 封装
  - `wherePaths(name)` — Windows where.exe 查找
  - `quoteWindowsArg(value)` — Windows 参数转义
  - `spawnExecutable(executable, args, options)` — .cmd/.bat 处理
  - `findExecutable(candidates)` — 去重循环 + existingFile
  - `createDisabledSkillNotice(providerName, settings, allSkillNames)` — 参数化的禁用 skill 提示

- `src-node/run-claude.mjs`：删除本地 `existingFile`、`execText`、`wherePaths`，改用 runner-utils 导入
- `src-node/run-pi.mjs`：删除 5 个本地工具函数 + `createPiDisabledSkillNotice`，改用 runner-utils
- `src-node/run-codex.mjs`：同 Pi 处理方式
- `src-node/claude-runner.mjs`：删除本地 `existingFile`（statSync 版），改用 runner-utils 的 existsSync 版

**效果**：净减少 ~55 行，消除 3 处重复，修复 Pi/Codex 的 `execFileSync` 未导入 bug。

## #5 工具问答数据 JSON-in-String 存储

**问题**：`ChatMessagePart.text` 在 `kind: 'question'` 时存储 JSON 字符串，消费者需调用 `parseToolQuestionPartData` 解析，类型不直观。

**改动**：

- `src/ai-types.ts`：`ChatMessagePart` 新增 `questionData?: ToolQuestionPartData` 字段
- `src/chat-runtime.ts`：构建 question part 时同时设置 `questionData` 和 `text`（向后兼容）
- `src/lib/ai-utils.ts`：新增 `getToolQuestionData(part)` 函数，优先读 `questionData`，fallback 解析 `text`
- `src/chat-ui.tsx`：改用 `getToolQuestionData(part)` 替代 `parseToolQuestionPartData(part.text)`
- `src/auto-tasks.ts`：构建 question part 时同时设置 `questionData` 和 `text`

**效果**：question 数据直接以结构化字段存在，消费者无需 JSON 解析。保留 `text` 字段向后兼容旧会话数据。

**效果**：1099 行 mod.rs 拆为 5 个职责清晰的模块。`send_ai_chat_message` 从 282 行简化为 ~30 行编排代码。

## src/ 目录重组

**问题**：`src/` 下约 20 个平铺文件，AI 相关和宠物相关逻辑混在一起，难以快速定位。

**改动**：

  - `chat-runtime.ts`、`chat-ui.tsx`、`file-drop-handler.ts`、`bubble-layout.ts`

  - `pet-loader.ts`、`pet-windows.ts`、`pet-window.ts`、`pet-position.ts`
  - `pet-scale.ts`、`interaction.ts`、`context-menu.ts`、`animation-data.ts`

- 入口文件（`main.ts`、`renderer.ts`）、`types.ts`、`workspaces.ts` 留在根目录
- 更新 ~25 个文件的导入路径（外部 → AI/Pet 组使用 `@/ai/...` 或 `@/pet/...`，组内互引保持相对路径不变）

**效果**：`src/` 根目录从 ~20 个文件缩减为 4 个入口文件 + 2 个子目录，AI 和宠物逻辑各自聚合。
